# 单卡和双副本的推理调度对照

模型 Qwen3-0.6B，BF16 贪心解码，单机 RTX 4090。每卡使用一份模型和 448 MiB 持久 KV；两张卡的总 KV 预算为 896 MiB。PyTorch 2.11.0+cu128，FlashAttention 2.8.3.post1，驱动 595.99.02。nano-vLLM 源码固定在 bb823b3，权重 SHA-256 与仓库 README 的 CPU 实验相同。

两条不同轨迹各含 300 个预分词请求。每组 8 条、间隔 220 ms；提示长度 500–511，输出长度 8–16。每种部署在同一条轨迹上重复 3 次，第二轮反转执行顺序。每格是三次独立运行的中位数，P95 列先在各轮内统计再取中位数。达标请求须同时满足首 token ≤250 ms 和每次后续 token 间隔 ≤100 ms。原始记录还提供 token 间隔 P95、各卡分流数和输出对照。[逐轮 JSON](rtx4090-replicas.json)

固定原生调度和轮询，混合流量下增加副本后，完成吞吐约为单卡的 1.51 倍，排队延迟大幅下降。双卡完成速率已接近输入速率（约 36 请求/s），本次负载只能说明这一到达率下的表现。每卡 KV 配额固定，扩容同时增加了计算资源和总 KV 容量。

固定双卡和保护策略，混合流量下缓存亲和比最短队列多命中 23 个前缀，完成吞吐相差约 0.08 请求/s。独立前缀下二者都执行最少未完成请求规则，仍观测到 P95 差异，显示真实到达时刻与 GPU 返回先后会影响分流。单卡保护策略大幅降低重算量，但独立前缀场景下达标数从 14 变成 13。

每组均实际生成全部 300 条请求的目标 token 数。不同调度改变批形状、缓存命中及抢占后的执行路径，BF16 贪心生成的完整序列有差异；逐轮字段 `exact_vs_first_stock` 对照该流量第一轮单卡原生输出。这里统计的是固定输出长度下的服务性能。流量由合成 token 组成，未评估业务答案质量。计时包括主机控制进程、IPC 和模型执行，HTTP 与网络传输在本次实验范围以外。
